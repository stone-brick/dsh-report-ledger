# 开发者模式：只在开发此插件时存在的代理

默认关闭（`config.devMode` 必须是字面量 `true`）。这是本仓库自己的开发期回路，不是给使用者的功能；门槛是仓库本身——名单 `dev/agents.yml` 不在 npm 包的 `files` 白名单里。

协作模式该怎么定，人类开发者看不到模型的使用习惯——哪些参数反直觉、一次交接实际要几轮、哪一步非回读正文不可。这些只有代理在使用中才会暴露，所以插件的迭代本质上要靠代理的真实使用作为测量。本节就是这个开发期回路。

**这些代理是插件自己的状态，DSH 看不到它们。** 早先的版本把它们注册成了 harness 预设——那是错的：预设是部署层面的事实，会出现在所有使用者的预设选择器里，并随部署存活，等于把开发产物泄漏进产品设置。现在：

- 开发代理是**插件自己开的会话**（`dev_agent_start`，走 `peer_start` 同一套同伴机制）；
- 某个会话属于哪个条目，记在插件自己的文件 `$DSH_HOME/report-ledger/dev-agents.json` 里——不在会话头、不在预设、不在 DSH 的任何地方；
- 提示词段按这份绑定路由，所以"谁是开发代理"只有插件自己知道。

## 开关与门槛

`config.devMode`，默认 `false`，而且**严格**：只有字面量布尔 `true` 才算打开（手写的 `"true"` 不算）。关着的时候插件不注册任何东西——没有 section、没有工具、不读任何文件。

**真正的门槛是仓库**：名单 `dev/agents.yml` 在检出里、且不在 npm 包的 `files` 白名单里。所以装了 tarball 的部署，无论 config 怎么写，都拿不到开发代理——复刻仓库才可用。

## 名单

名单是数据，不是配置：`dev/agents.yml` 放在**仓库里**，随分支和检出走。于是 `report_author(worktree:true)` 分出来的隔离检出可以带一份不同的名单——候选实现和量它的那份名单一起移动。

```yaml
agents:
  - id: report-ledger:dev/probe       # 条目 id，也是绑定文件里的值
    name: 开发探查者                    # 会话的显示名（不是预设名）
    description: 真实使用账本，把摩擦写成可复现的证据
    order: 10
    promptFile: prompts/probe.md      # 相对本文件所在目录解析
```

`prompt` 内联也可以；两者都写会被判为错误并跳过该行。

## 它做的两件事

1. **开一个会话。** `dev_agent_start(entry, task)` 用同伴机制建一个独立会话，把 `session → entry` 写进绑定文件，然后用一份汇报把任务交给它。**先绑定、后投递**——第一次装配就是第一轮，晚一轮到的角色等于没有。它照样计入同伴预算，照样能被 `report_list` / `peer_list` 找到。跑完一轮转为非驻留后，开启它的那个会话可以用 `peer_wake` 把它叫回来（名册的 `startedBy` 决定谁有权，不占新名额，账本顺带把欠它的投递送进去）；角色提示词段在重新装配时按绑定文件求值，所以回来的仍是同一个角色——前提是绑定还在。
2. **把一段提示词只投给它。** 第三段 `systemPrompt.section`（order 202，紧跟协议 200 与伙伴契约 201），文本按装配求值：取 `agent.id` 去绑定文件里查，命中返回该条目的正文（退役条目追加收尾指令），否则返回空串——空段渲染时丢弃，所以其他 agent 的提示词一个字节都不变。`interpolate: false`：名单里是散文，`{{` 必须保持字面。

## 增减代理怎么生效

改 `dev/agents.yml` 不会触发重建——HMR 盯的是 `lib/`，不是 YAML。所以有一个只在开发者模式下注册的工具 `dev_agents_reload`：重读名单与归档索引，返回启用/退役条目、每个条目绑定了几个会话、以及绑到已消失条目上的孤儿会话（它们会失去角色提示词），外加每个坏行的行号与原因。

坏行逐条隔离：一行只损失它自己。这里没有"注册失败"这种状态可查——插件不向 DSH 注册任何东西，所以也没有被选择器过滤掉却假装成功的可能。

## 退役一个开发代理

**不要删条目，改成 `retired: true`。** 删掉的那一行会让已绑定会话的提示词在下一次装配时变空——它还在跑，但已经不知道自己为什么存在。退役条目的作用：**不能再被启动**，但已绑定的会话继续收到**自己的提示词 + 一段收尾指令**，让它用 `report_handover` 把汇报、检出与待送达交出去。

`dev_agents_reload` 会单独列出 `retired:` 一行与绑定的会话数；交接完成后手上有哪些东西，以 `report_handover` 的返回为准。

## 归档：让结论活过这次检出

账本落在 `~/.dsh`，**不随仓库走**；fork 的人只有 `dev/`。所以值得带走的不是汇报本身——原始汇报的对话对象已经不在，回放它们只花上下文——而是**结论**。

- `dev/archive/<topic>.md`：蒸馏件。保留结论类小节（`结论 / 决定 / 建议 / 风险 / 发现 / 未决 / 驳回 / 缺口 …`）全文，列出**全部小标题**，被省略的小节逐条点名。单文件 16 KB 预算，超了明说 `truncated` 并指向账本原文——隐藏省略的蒸馏比不蒸馏更糟。
- `dev/archive/index.yml`：**生成物，不要手编**。注入开发期提示词的只有它：每个主题一行（主题 — 一句话摘要 — 文件路径），最多 40 行；细节按需读文件。
- `dev_archive`（仅开发模式）：按 `task` 或显式 `reports` 选汇报、写文件、重建索引，并把新索引块**立刻**装进下一次装配。**永不"整本账本"导出**——账本是机器全局的，混着与本插件无关的工作，工具在没有选择条件时直接拒绝。
- 这是账本自己那条原则的延伸：进提示词的是缩略，正文按需打开。归档文件里会带上汇报编号与 contribution 标题里的会话 id：对 fork 没有意义，但保留了"谁在何时说了什么"的痕迹。

当前已归档六个主题（来自发布前审计）：`views` / `canvas` / `host-http` / `worktree` / `peers-tools` / `release-eng`。

## 两个已知边界

- 开发代理的**会话**仍然出现在会话列表里——它就是一个真会话。DSH 看不见的是"它是开发代理"这件事，而不是"这里有个会话"。要藏得更深只能藏会话本身，那是另一个决定。
- 绑定文件是本机状态：`$DSH_HOME` 里的它不随仓库走。别的检出拿到名单后，需要自己用 `dev_agent_start` 启动它自己的会话；旧会话不会被"认领"。
