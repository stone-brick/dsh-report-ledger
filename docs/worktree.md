# 工作区：一份汇报一个 git 检出

这是**可选功能**，默认关闭。本文写清「独立」到底独立了什么、占用与清理的全部规则，以及它已知的每一条限制。

打开后，`peer_start` / `report_author` 加 `worktree:true` 会为该汇报分配一个**独立的 git 检出**（`git worktree`），分支名由报告号派生：`dsh/R-0007-<主题 slug>`。主题若是纯中文，slug 退化为空，分支就是 `dsh/R-0007`——合法且仍可反查。

不需要它的部署付出的代价是**零**：没有 git 调用、没有目录，工具里也**不出现** `worktree` 参数。

## 真正被隔离的是什么

"独立检出"极容易被读成"独立环境"，而两者差距很大，所以边界写清楚：

| 面 | 隔离？ | 说明 |
|---|---|---|
| 工作目录里的文件 | ✅ | 各一份副本，路径级写冲突不存在 |
| `index`（暂存区） | ✅ | 并发 `add` 不争锁 |
| `HEAD` / `ORIG_HEAD` / merge 中间态 | ✅ | 每个检出私有 |
| 分支占用 | ✅ | **唯一的强互斥**：一支分支同时只能被一个检出签出 |
| `config` | ❌ 共享 | 一个检出改配置，全体被改 |
| `hooks` | ❌ 共享 | 一个检出装钩子，**此后所有检出的每一次提交都会跑它** |
| 对象库 / `refs` | ❌ 共享 | 物理只有一处 |
| 检出之外的一切 | ❌ | 端口、数据库、容器、`%TEMP%`、包管理器全局缓存 |

**所以它提供的是"可见、可归属、必须显式和解"的冲突，而不是"没有冲突"。** 两个检出改同一行，两边提交都会成功——冲突只是被推迟到合并时爆发。区别在于那一刻它是**响亮的、带冲突标记的、能归属到两条分支（也就是两个代理）**的，而不是一次静默的覆盖。

## 三个维度，刻意分开

| 维度 | 存在哪 | 生命周期 |
|---|---|---|
| **绑定** | 报告 front matter 的 `worktree` 字段 | 作者写入，**永不清除**——账本必须一直记得哪些检出是自己建的 |
| **占用** | 跳流派生（`leased` / `released` / `reclaimed`） | 每次交还、结案或显式清除时变化 |
| **归属** | `worktree.allocated` | 创建时定死 |

混起来会立刻出事：把"绑定"当"占用"，一份结案报告就会**永远占着**检出；把"占用"当"归属"，账本就会去删**别人建的**目录。占用为什么是派生的而不是一个字段——因为账本自己的信条就是这条路（待投递邮箱 `pendingTargets` 同样从跳流派生），而一个字段迟早会和历史对不上。

## 占用就是锁

**一支分支同一时刻只能被一份活着的汇报持有。** 裁判查两层，两层都必须过：

1. **git 查现实**——这个检出真的存在吗？真的在这条分支上吗？这条分支真的没被别的检出占着吗？
2. **账本查意图**——有没有另一份活着的汇报已经认领了它？

只查 git 会**说不出该找谁**（git 只报路径，而路径不是同事）；只查账本会**看不见人手建的检出**。两层对不上时如实报出，绝不静默抹平。

```
report_lease    认领一个已存在的检出（人手建的、上一份汇报留下的、自己交还过的）
report_release  交还占用；检出原封不动留在磁盘上，结束的只是"占用"
report_close    结案 = 自动交还，并按配置决定磁盘处置
```

`report_lease` 的 `branch` 可以省略：**分支从检出本身读出**，所以存进账本的是 git 报的真实分支与真实 commit，而不是调用方声称的。只有想强制校验时才传它。`path` 必须是**绝对路径**：相对路径在不同进程里指不同目录，所以会被直接拒绝，而不是按当前进程的 cwd 解释。

**没有"接管"策略**：缺席的持有者不会被抢走检出。它必须自己交还或结案——一个可能只是慢的代理，不该因为"没回应"就丢掉工作。被拒绝时会点名持有者**和它的作者们**。

## 一个硬预算，一个告警阈值

| 配置 | 量什么 | 超了会怎样 |
|---|---|---|
| `maxActive`（默认 4） | 同时被**占用**的检出 | **硬拒绝**，并点名占用者、以及它此刻是否在线 |
| `maxRetained`（默认 4） | 结案后仍留在磁盘上的检出，**按仓库分别计数** | **只告警，不删除。** 维护视图会提示超出阈值；清理由人显式执行，或结案时用 `remove-if-clean` |

**分配永远不会删除检出。** 它只创建或拒绝；旧检出不会因为下一次分配而消失。把「腾磁盘」做成分配的副作用，等于让一次无关的创建动作拥有删除别人工作目录的权力；现在这个权力只留在显式的结案动作里。

## 安全轨

- **适配器里没有 `--force`。** 没有任何调用方能覆盖 git 的保障：脏检出删不掉、被别人占着的分支抢不走。
- **结案默认不动磁盘**（`onClose: 'keep'`）。开了 `remove-if-clean` 也只删干净的；被拒绝时**原样抛出 git 的话**，而不是吞掉。
- **删除的授权来自报告**：只有 `allocated: true` 的检出才可能被结案动作移除，人手建的目录账本永不碰。
- **结案移除不会动别人正在用的检出。** 移除前按路径与"任何活着的占用"比对：若另一个汇报已经采纳了它，移除被拒绝并点名持有者。
- **人手删掉的检出会被一次性发现**：下次分配时账本记一笔"已经不在磁盘上"，此后不再重复检查——而不是每次重新审视、并被误报成"有未提交改动"。
- **`reclaimed` 是终态**：`reclaimed` 与 `released` 是两个状态。账本按 `remove-if-clean` 移除一个检出时会记下 `reclaimed`；此后它不再被当成候选，也不会被误报成"异常消失"。这一条不是洁癖：一次**故意**的移除如果读起来像异常，那条警告就会在推荐流程上每次都响，而读者会学会忽略它。

## 配置

```yaml
worktree:
  enabled: true          # 总开关，默认 false
  root: D:/somewhere     # 检出根目录；默认在仓库的兄弟目录：<仓库父目录>/.dsh-worktrees/<仓库名>/
  onClose: keep          # 结案处置：keep（默认）| remove-if-clean
  maxActive: 4           # 同时被占用的上限
  maxRetained: 4         # 结案后留在磁盘上的告警阈值（按仓库分别计数，不自动删除）
  relativePaths: false   # 用相对路径写 gitfile
```

`relativePaths` 不是纯外观：它启用 `extensions.relativeWorktrees`，把 `core.repositoryformatversion` 抬到 1，**旧版 git 会直接拒绝访问该仓库**，所以默认关闭。分配前还会先问 `git --version`：低于 2.48 时直接拒绝并说明，而不是让每次 `git worktree add` 死在 `unknown option 'relative-paths'` 上。

**子模块是硬闸门**：仓库里有 `.gitmodules` 时分配被拒绝。git 自己的手册说多检出仍属实验性、子模块支持不完整，且含子模块的链接工作区**连 `move` 都不行**——这里选择拒绝而不是提醒。

## 在界面里

报告行上会出现该检出的标记（分支名），**色调就是占用状态**：绿色 = 正在被占用，蓝/灰 = 已交还或已被显式清除。点一下即以它为条件过滤——与任务标记同一套交互，复用搜索框，不新增第二套过滤机制。


## 已知限制

工作区相关的限制（该功能默认关闭，未开启时都不适用）：


- **隔离是有限的。** 独立的是工作目录与索引；`config`、`hooks`、对象库与检出之外的一切都共享。装一个 hook 会影响所有检出的每一次提交。
- **没有"接管"策略。** 缺席的持有者不会被抢走检出；只能等它自己 `report_release` 或结案。
- **维护视图只报告，不修复。** `GET /api/report-ledger/worktrees` 会列全**账本已用过的仓库里**每个检出的磁盘实况与每一处异常，但清理仍然是人（或 `report_close` 的 `remove-if-clean`）的动作。自动 `prune` 会毁掉一个被手工搬走、却从自己那侧照常可用的检出，所以它不在这里做。它的 `retained` 是全账本口径（含非账本自建、报告未结案的检出）；分配侧只数当前仓库结束的账本检出，而且只用于告警，不删除。
- **没有自动回收。** `maxRetained` 只是维护视图的告警阈值；分配不会删除旧检出，平时也不会主动整理。清理只能显式执行：`report_close(worktree:"remove-if-clean")`，或手工删除。
- **旧配置 `worktree.reclaim` 会被忽略并告警。** 它不再有任何效果；看到告警后删掉该字段即可。
- **绑定不能清空，只能覆盖。** `report_amend` 不管绑定；要改正一个指向已消失检出的绑定，办法是 `report_lease` 认领另一个有效检出。
- **含子模块的仓库直接拒绝分配**，没有逃生开关。
