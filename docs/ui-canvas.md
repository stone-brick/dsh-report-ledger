# 画布：卡片图的设计、几何与实测

右侧栏的拓扑画布是怎么做出来的、为什么一个图库都不引、几何规则被哪些断言钉住，以及每一项决定背后那次实测的数字。**这是设计记录**：要知道画布能做什么，看 [界面](ui.md)；要改它，这里是唯一的依据。

## 沿革：竖向泳道（已被取代）

列表上方是一张**竖向泳道图**：一条泳道 = 一个会话（列），时间向下（行），每一份汇报画成发起者泳道上的一个节点，它的传递路径画成跨泳道的边。

（**这一版已被卡片画布取代，视图与模型也随之删除**：图表位先由卡片画布接手，随后画布整体搬进**右侧栏的标签页**，见下面「拓扑：卡片画布」与「画布住在右侧栏」。下面这段留在这里的是**仍然成立的设计结论**——它们全部被卡片画布继承，换掉的只有"节点不承载内容"这一件事；`TopologyView.tsx`、`topology-model.ts` 与钉住它的 `scripts/topology-check.ts` 已一并清理。）

```
泳道(会话, 树序) →   afcbce3a │ 01edba72 │ 05286f38 │ …  │ 树外
时间 ↓                        │          │          │    │
  19:00  ●R-0001 ─────▶──▶──▶┄┄▶  (主送实线、抄送点线)
  20:30            └╌╌●R-0002 ──▶  (线程竖向、回执向回)
  19:45                        ●R-0003 ┄┄┄┄┄┄┄┄┄┄┄┄▶
```

**为什么是竖向、为什么不需要图引擎。** 这个标签页本来就纵向滚动，时间向下与下面列表的阅读方向一致；而布局**不需要任何图算法**——泳道序就是子树 DFS 序（列表缩进用的同一个序），行序就是时间序（列表排序用的同一个序），两个 rank 都是现成的。通用引擎要解的是**交叉最小化与端口路由**，是这份数据没有的问题，却要为此付出：`elkjs` 是 EPL-2.0/GPL 且解包 8 MB，`d3-dag` 虽是 MIT 但为最优交叉最小化拖进一个线性规划求解器，`@xyflow/react` 1.2 MB 且自带一套样式表。所以这一版**零新增依赖**，几何由当时那个纯模块给出（`topology-model.ts`，已随这一版删除；卡片画布沿用了同一个立场）。

**它是什么、不是什么。** 它是**总览**，不是第二个阅读面：节点点击后**滚到列表里那张卡片并展开**——正文、传递路径、待送达仍在同一个地方读。这样图不必处理 4000 字的正文，也不承担"键盘/读屏唯一入口"的责任：列表一直在，图只是加在它上面。

**树外会话有一条共享泳道。** 被 cc 进来的、或发起者在别的树里的汇报，如果没有这条泳道就无处落点；它们全部落在最后一列 `树外`。

**这条横向滚动是刻意的。** 视图自己有一个受控的滚动框（宽出即可横向滚动、高限 46vh），与之前那个"内容撑破整个标签页、滚动条只在最底部够得着"的意外滚动条不同：这里是**包在一个框里**的。默认几何（泳道 120px、沟槽 84px）是照"八条泳道刚好放进一个标签页"定的（实测 1108px，无需横向滚动）。

**布局当时被 34 条断言钉住**：泳道序等于子树序、节点落在发起者泳道、边落在收件人泳道且同一行、重复收件人只画一条、发给自己的不画、树外落点归到共享泳道、线程边只在线程两端都被画出时才存在、空输入不产生 NaN、同一输入给出逐字节相同的几何（见 `scripts/topology-check.ts`；该脚本已随这一版一起删除）。

**图例必需，逐边文字不必需。** 四条线型如果没人解释，读者只能猜——所以标题旁有图例，而且它的样例**用的就是画线的同一批 class**（`edgeClass()`），改了线的样子不可能留下一个说谎的图例。但**每条边都挂文字是重复的**：线型已经编码了主送/抄送/共写。所以文字只在**悬停某一份汇报时**出现，回答的是"我正在追的这条路径是什么关系"。这也正是 Mermaid 泳道文档里 "Label Cross-Lane Handoffs" 想说的那件事，只是它的载体是线型 + 悬停，不是常驻标签。

**线程走泳道之间的缝隙。** 父子连线跨行，直接画曲线会穿过中间的行与节点；所以模型为它算出 `viaX`——**一条泳道边界**，节点都居中在泳道里，边界离任何节点都有半个泳道远，连线因此完全不碰节点。这条规则也进了断言（边界必须严格落在两列中心之间、且从不落在任何一列的中心上）。

## 规模：布局是免费的，渲染才是成本

在一份 300 份汇报的账本上量过（隔离实例，真实浏览器）：

| 量的是什么 | 结果 |
|---|---|
| **纯布局**（500 泳道 × 5000 汇报 × 7916 条边） | **3.4 ms**（20 次中位数）——布局永远不是瓶颈 |
| 渲染元素（300 汇报，改之前） | 5469 个：838 条边各自一个 `<path>` + 838 个箭头 `<polygon>` + 300 条分隔线… |
| 悬停一次（改之前） | **89 ms** —— 每次 mouseenter 要改 831 个 `<g>` 的透明度 |

两处修法都有实测回报：

1. **同类边合并成一条 `<path>`，箭头改用 SVG `marker`**——边本来就不可点击，一条边一个元素只买到"每次重绘一个形状"。箭头是路径的装饰而不是节点，交给 `marker` 后额外元素为零。
2. **淡出只作用于"边的那一层"，绝不走后代选择器。** 这是最有价值的一条：单独翻写一个被**后代选择器**匹配的属性（`[data-hot] … :not(…)`）本身就要 **35 ms**，因为浏览器要为整棵子树重算样式，**哪怕最终没有任何可见变化**（我用注入 CSS 把结果改成 `!important` 覆盖也降不下来——覆盖只改结果，不减重算）。所以节点干脆不淡出：追踪一条路径时该退到后面的是**关系**，不是参与者。

结果：元素 **5469 → 2689**、边路径 **838 → 10**、箭头多边形 **834 → 0**、悬停 **89 → 44 ms**（最好的一次 16–19 ms，即一帧）。

3. **窗口化**：只渲染滚动框里真正看得见的那几行（上下各留 4 行 overscan）。300 份汇报时任意时刻只渲染 14–20 行，元素 **2689 → 265**、悬停 **44 → 32 ms**——而 32 ms 就是**测法的地板**（每次采样等两帧，60 Hz 下约 33 ms），也就是已经没有可测的开销了。四个滚动位置都验过窗口覆盖视口（顶部/中部/底部/偏后），粘性表头在位，没有空白带。

⚠️ **窗口化引入的每个派生列表都必须依赖窗口。** 我把节点列表的数据源从 `layout.nodes` 换成 `shownNodes`，却忘了把它加进 `useMemo` 的依赖数组——结果是**边与时间轴跟着滚动，只有节点不动**，看起来像"滚了但内容没换"。这类 bug 在浏览器里一眼可见（四种滚动位置一测就抓到），而七套断言全都发现不了：纯模型没有错，错的是"React 有没有重算"。所以窗口化的断言只覆盖"哪些行该在窗口里"，覆盖不到这一层，这一点要说清楚。

## 卡片画布：设计、实测与代价

泳道版证明了"关系和归属可以画出来"，但它有个致命弱点：**节点是芯片，不承载内容**——一份汇报在图里只剩一个 `R-0001`。下一版改成卡片图，两个决定已经定了：

- **会话 = 框**（蓝图里 Comment 那种：带标题、底色，可整体折叠），归属靠**包含**表达，不靠位置；
- **全 canvas 渲染**（不是 SVG、不是 DOM）。

**卡片图的设计**：帧内按时间堆叠汇报卡片；线有方向与语义——主送实线（卡片出 → 对方帧的收件口）、抄送短间隔虚线、共写点线（共写者帧 → 卡片入）、线程墨色实线（父卡下缘 → 子卡上缘；相邻卡走 8px 卡间短跳，隔了卡才绕沟槽）。**三档 LOD**：完整卡（≥0.8）→ 紧凑卡（0.4–0.8）→ 色条（<0.4），配矩形剔除。

⚠️ **一条硬规矩：卡片尺寸是 LOD 常量，绝不由文字度量决定。** 否则布局就依赖 canvas 度量、变成不可测的东西，而"缩放到全局时有多少个绘制对象"恰恰是这套设计唯一站得住的标准。文字在**绘制时**裁剪/省略。

**参考里真正可用的部分**

| 参考 | 学到什么 |
|---|---|
| Unreal **蓝图** | 卡片节点的解剖（标题栏 + 引脚 + 有类型的线）与 Comment 框做分组。（⚠️ Epic 的文档页是 JS 渲染的，抓不到正文——这部分是通行认知，不是引用） |
| **draw.io / maxGraph** | ① 它**用的是 SVG 不是 canvas**：`packages/core/src/view/canvas/` 下只有 `AbstractCanvas2D`(13.6 KB)、`SvgCanvas2D`(47.6 KB)、`XmlCanvas2D`(28.2 KB，是导出不是绘制)——所以"照 draw.io 做"**不支持**"改用 canvas"。② 真正值钱的是架构：**画家抽象**（`state` + `save/restore` + 变换 + `rect/roundrect/text/begin/moveTo/quadTo/curveTo/fill/stroke`），形状只管画模型坐标。③ `begin()` 建**一个** `<path>`，之后所有操作累积、最后一次 `setAttribute('d', …)` 提交——正是我这边实测出来的"合并路径"（838 条边 → 10 条）。④ 坐标统一走 `(x + dx) * scale` 并**取整**，奇数描边宽补 `translate(0.5, 0.5)` 求清晰。⑤ 文字**不跟几何一起画**：`foreignObject` + 真 `<div>` 交给浏览器排版，并留住节点引用让 `updateText` 只挪位置。⑥ 命中的容差靠克隆一个更粗的透明描边。 |
| **React Flow** 的性能文档 | node-graph 在规模上的共识：只渲染可见元素、memo 化自定义节点、别让视口变化触发全量重渲染。（[reactflow.dev/learn/advanced-use/performance](https://reactflow.dev/learn/advanced-use/performance)） |
| Excalidraw | **双画布**：静态层与交互层分开。（这条来自一篇二次分析而非其源码，标注待确认；但理由与我们的实测一致——悬停曾是我们最大的热点） |

**为什么一个图库都不引**（实测与查证，不是好恶）

| 候选 | 事实 | 判定 |
|---|---|---|
| **konva** | MIT、**零运行时依赖**、canvas，且自带文字 wrap/ellipsis 与命中检测 | 用我们的真实用法建了探针：**+491 KB raw / +115 KB gzip**，而当前客户端半只有 89 KB raw——**5.6 倍**。换来的实际只有换行与命中两件小事（约 65 行），而**保留式场景图对我们是负资产**：架构是"纯模型 → 绘制一遍"，引入场景图等于维护第二份可变几何，正是本仓库已经踩过的那类 bug（边跟着滚、节点没动）。**不引。** |
| **@antv/g6** | MIT，概念上最省（combo 就是"框"，自带布局与小地图） | **11 个运行时依赖**／解包 7.6 MB／自定门槛 400 KB gzip；且 `@antv/layout` 有 **WASM 动态分块**路径——单文件插件 bundle 里动态分块会 404，与当初否掉 Mermaid、elkjs 是同一个坑。**不引。** |
| cytoscape | MIT、零依赖、canvas | 节点模型是"形状 + 标签"，**做不了多行卡片**，正是新设计最在意的部分。**不引。** |
| maxGraph（draw.io） | Apache-2.0，路由/端口/泳道形状齐全 | 渲染是 **SVG**，与"全 canvas"冲突；只取几何/路由又得半个大库。**不引，但抄它的画家抽象。** |
| Excalidraw / tldraw | — | 前者是编辑器应用（渲染器不对外复用），后者生产使用需要 license key。**不引。** |

**Step 0 已落地：`src/client/cardgraph-model.ts`（133 条断言）**

先做模型、再写画布，因为这份设计要证明的全是数字：哪只帧装哪张卡、线从哪条边走、两条线落在同一条帧边上时各自落在哪、一个视口能看见什么。模型里已经钉死的规则：

| 规则 | 是什么 | 为什么 |
|---|---|---|
| **列 = 子树深度** | 同深度的帧在同一列里自上而下堆，列序即 DFS 序 | 父亲永远在孩子的左边，主送/线程天然是短横线；不需要 rank 计算 |
| **帧高 = 标题栏 + 内边距 + 卡片堆** | 空帧也保底一个最小高度 | 空会话仍然读得出一只框，而不是消失 |
| **卡片刻度 = LOD 常量** | 文字只影响绘制，不影响几何 | 见上面的硬规矩；实测断言：400 字主题与 3 字主题拿到**同一个矩形** |
| **输入顺序无关** | 卡片按 `created` 排，平局用 report id；连边也按卡片序走 | "同一本账，同一张图"，打乱输入重建 byte 相同 |
| **端点均分（帧与卡片）** | 同一帧同一边**或同一卡同一边**的线，按远端坐标排序后在可用边内等分（卡片留 10px 内缩） | 两条线永不落在同一像素；卡片端不再"所有箭头指同一个点"——这是改之前最刺眼的一处 |
| **线走通道，且各占车道、拐角带圆角** | 出生入死都先竖直出 6px stub，再走本列**列沟槽**；跨列时在两条 gutter 之间挑一条**没有帧的横路**（帧间 `frameGap` 的中点，或图的上/下 margin），最后从目标自己的 gutter 进入。同一沟槽/同一横路里的线按 9px **车道**错开，且车道**按端口 y 排序**分配（端口在上面的线走上面的车道），所以平行段不重叠、入沟槽前的短横段也不交叉；折线正交、去重/共线合并 | 只有两端各自的帧会线被穿过（必须进出），中间的帧与**标题栏**一律不碰；断言钉住"任意一段不与无关帧相交""不与任何标题栏相交""不出画布" |
| **箭头留缝** | 箭尖停在目标前 3px，连线也画到那儿 | 箭头不再半个压在框线上 |
| **跨列直线（已被上一条取代）** | 旧行为：跨列直接连，可能穿过中间的帧与标题栏 | 这是上一版接受的代价；现在由通道布线取代，draw.io 式"细线压框"不再需要 |
| **矩形剔除取代窗口化** | 一切带 `bounds` 的东西（帧/卡片/线）用同一个 `cullByBounds` | 自由画布没有"行"可数；且**两端都在屏幕外、中段穿过视口的线必须留下**——泳道版为这条踩过坑，断言里复现了它 |
| **视口反变换** | `worldViewport` 把 pan/zoom 换成绘制坐标里的可见矩形 | 坏掉的 `scale`（0/NaN）退化成 1，绝不产生无限或反向矩形 |

这个模块现在**被视图引入**了（画布就是它画的），所以它不再对运行时零成本——代价与实测见下面 Step 2 的体积账。它由 `scripts/cardgraph-check.ts`（135 条断言，与另外几套一起进 `pnpm test`）钉住。

**Step 1 已落地：`src/client/cardgraph-painter.ts`（99 条断言）**

画家只认一个**结构化上下文** `PaintContext`——十来个方法（填充、路径、文字、一个变换），真 canvas 天然满足它，测试里换成一只**记录器**。于是"这条线被淡出了、那只框没有""画的是虚线还是实线""箭头落在哪个点"全都成了断言，不用开浏览器。这也是 draw.io 的画家抽象真正值钱的地方：换成 SVG 只是再实现一遍这个接口。

| 决定 | 是什么 |
|---|---|
| **绘制顺序：帧 → 线 → 卡片** | 线永远压在它穿过的框上（不会消失），而卡片的文字永远不会被线穿过 |
| **文字只在这里量** | `foldText`/`elide` 按 `measure` 折行：Latin 能在空格处断就断，中文按字断；按 (字体, 文本) 缓存，因为画布上每次测量都是一次同步排版 |
| **几何一点不看文字** | 断言把测量宽度从 1 改到 40：画出来的矩形与线段**逐字节相同**，而文字确实变了 |
| **主题走 token** | 16 个颜色槽 + 4 个字体 token（每个自带 size/weight/line-height/family），全部有兜底；重读靠一只**金丝雀 token**（页面底色）——它没动就不重读，于是每次重绘只多一次属性读取。**悬停单独一档蓝**：`accent` 跟的是 shell 的品牌墨色（浅色主题下近黑），用它标指针会把"指针在这"读成"这份被选中"；所以 hover 取 `--dsw-alias-button-info-hover`，选中仍用 accent，两者在断言里必须是不同的值 |
| **状态与线型同源** | 卡片左缘色条、状态文字、状态**形状**与四种线的色 + 虚实都取自同一套 token，和图例、列表的 `Tag` 语气一致 |
| **色相是第二线索** | 四类线各有色相（主送=业务蓝实、抄送=灰虚、共写=成功绿点、线程=主墨实）**且各有虚实**：灰度或色盲读者靠虚实仍能分开，颜色只是让扫视更快 |
| **状态是形状，不只是颜色** | 卡片页脚在状态词前画一个形状标记：进行中=实心圆点、已回执=对勾、已结案=方块。截图去色、色弱、"这块橙色到底是哪个状态"都不再需要猜；chip/compact 档没有页脚，也就没有标记（chip 用整卡底色表达） |

⚠️ **已知未做：坐标不做像素对齐。** draw.io 是在变换之后取整的，因为它的画布是 1:1 屏幕空间；我们的画布是缩放过的，要取整就得逐点换算到屏幕空间。先按抗锯齿走，等实测说糊了再补——这条留在这里而不是留在代码注释里，是因为它需要一个浏览器里的判断。

**Step 2 已落地：`src/client/CardgraphView.tsx`——在真实浏览器里逐条量过**

画布是两只层（静态 + 交互）、平移缩放、命中、**一个固定版式**、点开详情，全部做完，并且在**隔离实例 + 真实浏览器**里逐条验证（不是推理）。它现在住在**右侧栏的标签页**里（见 [`### 画布住在右侧栏`](#画布住在右侧栏本插件注册的标签页)），会话页那个标签页只剩列表——同一份数据不再有两处渲染。

| 验的是什么 | 结果 |
|---|---|
| 真的画出来了吗 | 底图 `946×420`、100% 不透明；像素里数到文字（8,976 个暗像素）、橙/绿状态色、蓝色线程——四种线型都落了墨 |
| **悬停只重绘交互层** | 底图 effect 的依赖不含 hover，悬停只走交互层；这条曾用「墨量相同」验收，对「重绘了但画得一样」不敏感，重绘次数待浏览器复测 |
| 悬停的代价 | 中位 **32.6 ms**，而每次采样等两帧的地板是 ~33 ms（60 Hz）——也就是**测不到开销**，与泳道版当初撞到的同一条地板 |
| 点击卡片 | 打开下面列表里的详情（`手工核对几何 dump` 出现在 DOM 里）——图表不另开阅读面 |
| 拖拽 | 平移了（按钮的 `left` 变了），**且没有触发打开**——拖动与点击靠 4px 阈值分开 |
| 滚轮 | **平移**（时间向下，滚轮就是往下读的轴）；`Ctrl/⌘+滚轮`以光标为中心缩放，一个 100px 的格子正好是按钮的 1.25 倍。两种手势下 `window.scrollY` 始终为 **0** |
| 版式不随缩放变 | 卡片尺寸固定，缩放只做变换：26% 与 125% 下是**同一种版式**（此前 26% 会切到芯片档，只剩帧标题） |
| 无障碍 | 7 张可见卡片各有一个**真按钮**（透明、带 `aria-label`），键盘/读屏可达；列表仍是完整路径 |
| 热重载 | 重建 `lib/client.js` 后浏览器**自己换掉**了插件（页内不刷新），这就是改完立刻能看到的原因 |

**三处是看了截图才改的**（不是想出来的）：

1. **首屏曾经是另一条规则，现在与控件是同一条。** 最早沿用「整张图塞进盒子」的 fit，结果是 **57%**——落在紧凑档，第一眼是一堵单行卡片墙。于是首屏改成「按宽度适配、不低于卡片档」（`clamp(…, 0.8, 1)`），而 fit 按钮仍是「看全貌」，两条规则各说各话。后来发现它们其实是同一个缺陷的两面：**档位由 zoom 反推、而 zoom 又必须由某个 layout 算出**，单次求解有时没有不动点——会话页实测 `58% ↔ 100%` 往复，窄会话列里 0.8 的下限还会把 750px 宽的图裁进 375px 的盒子。现在只有一条规则：**按宽度、在最富且自洽的档位、放大不超过一个控制步**（`MAX_FIT_ZOOM = ZOOM_STEP`）。首屏就是它，连点三次得到同一个数。**没有空解**：三档都不自洽时（如 2 列树 396–523px）把 scale 夹进最富可负担档的带内，而不是什么都不写——后者会让视图保留上一次变换，正是探测要消除的状态依赖。
2. **遮罩从 0.18 改到 0.55。** 第一版照搬泳道版的淡出值，截图一看：其它帧、标题、卡片**全都读不出来了**——追一条路径的代价是把整个上下文赔进去。泳道版自己早就得出过同一条结论的另一半（*该退到后面的是关系，不是参与者*），而画布遮罩比逐个形状淡出更粗暴，所以必须更轻。现在聚焦路径在顶上全强度重绘，其余保持可读。
3. **计数说的是"8 个框"而不是"8 个会话"。** 共享的"树外"帧也是一个框，把它算成会话就是在说假话。

⚠️ **顺带修掉一个自己在代码里埋的雷**：滚轮处理原先在 `setZoom` 的 updater 里调 `setOffset`——那是"在 updater 里做副作用"，React 有权把 updater 调用两次，于是每一格滚轮位移会被应用两遍、缩放会从光标下漂走。改成用 ref 读当前变换、在 updater 外面算。

代价：整个卡片画布（模型 + 画家 + 视图）让客户端半从 **89,360 B → 114,955 B**（gzip 24.86 → 32.17 kB），**+7.3 kB gzip**——而当初被否掉的 konva 光是库自己就要 **+115 kB gzip**。泳道版的 DOM 视图随之下线，这部分是被它自己腾出来的地方抵掉的。

把画布搬进右侧栏、并在面板内直接读详情，又让客户端半从 **114,955 B 长到 134,835 B**（gzip 32.17 → 38.88 kB，**+6.7 kB**）：标签页类型注册、`fill` 的盒高归属、共用读路径（`timeline-source.ts`）与共用详情（`ReportDetailView.tsx`）——最后两项是消重，不是新增能力。

**留下什么、重写什么**：泳道序（成为帧的排列序）、树外泳道（成为"树外"帧）、四种边的语义、窗口化（升级为矩形剔除）、单层淡出、合并路径、marker 箭头、图例、悬停文字——**全部保留**；泳道的"列 + 行 + 芯片"重写成"帧 + 卡片 + 线"。列表、详情面板、过滤、轮询完全不动。

## 画布住在右侧栏（本插件注册的标签页）

画布不再占用「汇报」标签页的版面，而是作为**右侧栏的一个标签页类型**住进产品自己的可停靠面板里。这一节记的是它落地时的决定与实测。

**注册三步，一个实现 id。** 类型进 `ctx.sidebarRightTabs`（`kind: ledger-canvas`、`priority: extension`、`guide` 一张胶囊，`order: 15` 落在产品的 `files(10)` 与 `terminal(20)` 之间），正文进 keyed 的 `sidebar.right.pane.tab`，两处用**同一个 `id`**；胶囊是**可发现性的唯一来源**——标签条的 `+` 只会重开引导页，而引导页就按这些胶囊列出类型，没有它这个标签页只能由代码打开。

**服务用 `ctx.inject` 等，不写进 `inject` 列表、也不用 `ctx.get`。** cordis 没有可选依赖形式：写进 `inject` 的 key 缺一个就会把这个插件的 fiber 打进 INACTIVE，而在 web boot 上那是**白屏**而不是少一个标签页；`ctx.get` 又读得太早——产品是在自己的 `apply` 里 provide 这个注册表的。`ctx.inject` 是唯一既可选又迟到的形式：服务出现时回调才跑，服务走了它还会再跑。

**两个服务面在本地按结构断言，不 import。** 客户端 bundle 的纯度门拒绝跨插件值导入，而且那个包的客户端类型不在第三方插件的可解析依赖集里——这与 `client/index.ts` 里对 `slots`/`locale` 的做法是同一条规矩。

**盒子的高度由面板给。** 画布现在只住在右栏（会话页那个 420px 固定盒已随画布搬走，非 fill 分支在 `src/` 里已无调用者）；停靠的面板反过来——高度是它给的，固定尺寸会让图漂在半空。`CardgraphView` 保留 `fill`：盒子照样测量，只是由宿主决定谁定高度。

**fit：按宽度、在固定版式下、放大不超过一个控制步**（`MAX_FIT_ZOOM = ZOOM_STEP = 1.25`）。宽度是目标，因为时间向下：横向是"必须装下"的轴，纵向是"拖着读"的轴。**画布只有一个档位**（`lod: 'card'`），所以 fit 不再探测：`fitTransform(..., { lod })` 直接按这一档的宽度算缩放，夹在 `[MIN_ZOOM, MAX_FIT_ZOOM]`。这样缩放只是变换，**线不会因为换档而重算、跳位**——上一版 `lodFor(zoom)` 让每次缩放重建一次几何，读者就看见线在跳。老探测路径仍在（非固定档位时走它，测试覆盖），但画布不再用。（纯几何在 `fitTransform`；`MIN_ZOOM`/`MAX_ZOOM`/`ZOOM_STEP`/`MAX_FIT_ZOOM` 由 `cardgraph-model.ts` 导出。）放大上限是为了**只有一张卡的会话**：否则"填满宽度"会要求几倍于设计尺寸的缩放，字号变大而信息没多（档位按固定尺寸绘制，超过 100% 只是放大），而且窄到那种程度时就算放到 250% 也填不满。控件文案随之从「适应窗口」改成「填满宽度」——它承诺的是铺满，不再是看全。

**滚轮平移、`Ctrl/⌘+滚轮`缩放。** 纵向成了主要阅读方向之后，滚轮就该是"往下读"这一件页面通用手势，缩放挪到修饰键。实现上两处刻意：**只有该轴真有溢出时才动它**（装得下的图不会被滚轮推歪），**行程到 12px 边距为止**（不会把图滚出盒子）；平移量按 `deltaMode` 归一（行 ×16、页 ×盒高），缩放对 delta 取指数（100px 一格 = 按钮的 1.25），于是鼠标格子与触控板捏合走同一条曲线。

**盒子变了就重新适应——但只跟随"没被读者接管"的视图。** 停靠、分栏、全屏都会在一个按旧盒子算出来的变换之下改变盒子，带着旧偏移的图会被新盒子裁掉（读起来像坏了，而不是像视图被保留）；可是刻意放大去看一张卡的人不该被打断。所以有一个 `fittedTransform` 标记：fit 成功置真，任何手动缩放或平移（± 按钮、滚轮、拖拽）置假，只有它为真时盒子变化才重跑 fit。盒子按值比较——观察者每次测量都交来新对象，重测不等于改变尺寸。

**点卡片 = 去「汇报」标签页读它，画布不掉高度。** 早先的做法是在画布下方再开一个详情面板，代价是把画布压成一半高（实测 619 → 278px）——而那正是这一列存在的理由。现在点卡片只做两件事：把这份汇报放进两界面共用的选择（`selection-bridge.ts`），再把会话区的「汇报」标签页切到前台；详情在那边按行展开，画布保持全高，选区、下钻、缩放全部留着。

**两个界面互相点亮指针，而且是同一档浅蓝。** 同一只鼠标，两个面：画布上悬停一张卡 → 列表里那一行淡蓝底 + 蓝描边；列表里悬停一行 → 画布那一份汇报的路径亮起（复用画布自己的聚焦绘制），环路与路径线都用 `--dsw-alias-button-info-hover`。桥只存一个 `hover` 和它的来源；**离开**只清自己发布的那个 hover，所以一侧的指针移开不会把另一侧刚点亮的行熄掉。打开状态由列表拥有（它才是读汇报的地方），画布只跟着它给选中卡加色——**选中仍是墨色 accent，指针才是蓝**：两者颜色在画家断言里必须是不同的值，否则"指针在这"和"这份被选中"就分不出来了。

⚠️ **鼠标点过的卡要还焦点给它脚下的画布。** 卡片的键盘路径就是"聚焦即悬停"，所以浏览器点按后把焦点留在按钮上，会让路径在指针离开之后继续亮着——一个看得见的脏状态，而它是**焦点**不是 hover。修法只有一行：鼠标激活（`event.detail > 0`）后 `blur()`，键盘激活（`detail === 0`）保留焦点。这条是浏览器里量出来的：指针移到空白处之后，行的底色与描边都清了，画布的遮罩却还在。

⚠️ **交互层只画指针，不画选中。** 遮罩与浅蓝路径都只属于 hover；打开的那份汇报由**底层**表示（卡的环与 id 用 accent）。这一条是被流程改出来的：点卡片现在会打开汇报，如果交互层还保留"没有 hover 时退回到选中"的老逻辑，那么**点一张卡就等于把整张图永久压暗**，而且读的人会以为是悬停卡住了。画家断言现在钉住"只给选中、不给指针时，交互层什么都不画"。

**传递路径从四列文字改成一条轨道，取的是 GitHub 时间线的形状。** 每一跳一行：

| 元素 | 做法 | 为什么 |
|---|---|---|
| 左侧轨道 | 圆点 + **中性色**竖线（`--dsw-alias-border-l2`） | GitHub 的连接线本身不带语义；语义在点与文字上，线只管串起来 |
| 圆点 | 动作色的环，**实心**=这一跳动了汇报（发起/主送/共写/回执/修正/结案…），**空心**=只是旁听或记账（抄送/阅读/工作区动作） | 颜色之外还有一档形状，灰度下也分得清"发生了什么"和"谁只是看见了" |
| 动作 | **底色胶囊**：色值取动作色，底色是同色 13% 透明（`color-mix`） | 文字要有块面才像标签；只描边会显得像按钮，且和引用芯片抢视觉重量 |
| 会话引用 | 发起者与每个收件人用**同一种** mono 芯片（`→` 隔开） | 箭头两边是同一类东西；一边裸文本一边带框会让人以为两端不同类。芯片悬停给全 id + 会话标题 |
| 备注 | 动作下方的灰正文（不再斜体） | 斜体在中文里几乎只是更糊；GitHub 的说明也是正文 |
| 时间 | 右对齐、`tabular-nums` | 列对齐才扫得快 |

列表用 `<ol>`：跳是序列，读屏应当听成序列。旧的 `1fr` 网格连同那条"备注把面板撑宽 426px"的老账一起删掉了。

**账本文件做成了会话里那种交付卡。** 不是"一行路径 + 几个按钮"，而是这个 GUI 已经在用的文件形状：**类型图标方块 + 文件名 + 一行浅色路径 + 右侧一个紧凑的原生打开控件**（默认应用图标 + `⌄`）。点 `⌄` 是默认打开 / 已注册应用列表 / 在文件管理器中显示 / 复制路径；复制从此在菜单里，卡片上只留一个控件。图标方块的配色照抄交付卡（浅色主题白 50%、深色主题 5%），类型由平台的 `FileTypeIcon` 按扩展名判——.md 拿到的是系统认识的那个 markdown 字形，不是我们手画的。

它**不是** import 来的：open-in-app 的按钮只作为**它自己的 slot 贡献**存在（`deliverables.file.actions`、`sidebar.right.tab.document.actions`），第三方插件既不能跨插件 import 组件（客户端 bundle 的纯度门），也不能渲染别人的 slot（slot 由宿主渲染，视图是子节点不是宿主）。公开的是它背后那三个 Session Remote 动词，所以 `path-opener.ts` 按本插件一贯的做法**只声明要调的形状**：`canOpenWorkspacePath` / `workspacePathApplications` / `openWorkspacePath`，用 `ctx.get('remote.session')` 惰性取得——服务晚到或被替换都不会丢控件。降级很清楚：没有 Remote/没有桌面/读取失败时，卡片照样在（图标与路径就是那个文件），只是右侧换成复制；一次打开失败把副标题换成红字，不弹东西。关联应用在**进入详情时就预取**（实测查询要 1–2 秒，等菜单打开再取会先空后满），没赶上时菜单里有一行「正在读取应用…」。⚠️ 一个逐字踩到的协议细节：wire 上 **`action` 只认 `reveal`**，"用默认应用打开"是**省略** `action`；发 `action: 'open'` 会被网关的边界校验拒掉（`gateway/input-invalid: wire field "request" failed boundary validation`），第一次真机点开就是这条红字。

**正文默认折叠，折起来看到的是 front matter。** 正文是汇报里最长、也最少被通读的一段：翻账本的人先要的是"谁 → 给谁、几跳、最后发生了什么"。所以详情的正文区是一个 disclosure（三角 + 「正文」），**默认收起**，收起时那一行就是 front matter 的缩略：状态 Tag、`from=` 与收件人短 id（悬停给全 id 与会话标题）、抄送、跳数、最后动作、任务标签——与列表行读的是同一组字段、同一批词。点开才渲染 `MarkdownText`，截断提示也只在那时出现。两个细节是刻意的：`aria-controls` 只在面板真的挂载时才给（指着一个不存在的元素比不给更糟）；换一份汇报时折叠状态复位（pane 可以原地换报告，而 disclosure 属于它下面那份报告）。


**图例就是过滤器，长线自己会说话。** 工具栏那四段线样不再只是说明：点一下就**静音那一类线**（`aria-pressed` 表达开关状态），再点恢复；一份汇报发给多个收件人时会织出一团线，"只看线程"是读图时最自然的问题。静音是**视图过滤**，`buildCardgraph` 只丢掉那些线（连端口也一起丢），卡片与帧一个像素都不动，所以不会触发重新 fit、读者当前的视图不动。另每根线在**中点**画一颗带底色光晕的小圆点（线短于 36 单位不画）——长线穿过好几个框时，方向与类型不必只从两端读。

**被汇报提到的会话也会成为帧。** 只画子树时，一个用户自己开的根会话的汇报常常发给**同一工作区里另一棵树**的会话——它们有记录、有标题，却不在 `sessions` 里，线只能全落进「树外」。`buildTimeline` 现在多做一跳：子树汇报里提到的、宿主记录里存在的会话补进 `sessions`（深度取 `delegationDepth`，标题照旧解析），并把这些会话相关的那批汇报也纳入——画布上因此出现真实的代理帧，「树外」只留给确实没有记录的 id。

**一个会话打开画布，看到的是它所在的整棵树。** 视图请求 payload 时给的是「当前会话」，而子树只是这棵树的一部分：被委派的 worker 的汇报几乎都指向父会话与兄弟，若按它自己的子树建图，那些线全落进「树外」，画布上连一个代理都没有。`buildTimeline` 现在先顺 `parentSession` 向上走到树根再建 payload（幂等、带环保护）；`树外` 只留给真正不在这棵树里的会话。

**帧边按端口加长。** 一条帧边上的箭头是**均分**在可用边上的：帧太矮、来线太多时，间距会小于一个箭头宽，箭头就挤在一起。`fitChannels` 现在按「每条帧边要几个端口」算出所需边长（每端口 14px），不够就给那只帧加高——帧下面的帧顺延，画布跟着变高。帧的高度是布局算出来的，这条照样只在模型里，不动画家。

**箭头也要留空。** 向下的箭头不是一条线：箭尖离卡边 4px、箭头本身 9px，整个头要占卡上方约 13px。之前只给「线」留了 6px 的行距，箭头后半截会探进上一张卡或帧标题栏。现在线程落点按 `THREAD_ARROW_CLEAR = 15px` 留空，`fitChannels` 把这一需要算进 `cardGap` 与 `framePaddingTop`；不足时模型还会把落点夹在标题栏之下——宁可在更小的空隙里画箭头，也不压标题。

**同帧线程不再出帧。** 同帧两张卡之间的线程，以前一律走列沟槽：在最左/最右列时那条沟槽就是画布外边距，于是线贴着帧边、每条穿一次帧边框，叠成一束。现在同帧（非相邻）的线程改走**帧内右侧空白带**——卡片右缘到帧边框之间那条没有卡片的窄带——每条线程一条 9px 车道，`fitChannels` 按车道数加宽 `framePaddingX`。线从此不出帧。

**帧内横穿。** 左列卡片向右出线时，先向右 6px 进列间空隙，竖直走到**右列最近的行间空隙**，在那一行横穿该列；更右的列再各自选一次行间空隙，逐列横穿到帧右边界，再从那里接正常的沟槽/横路逻辑。这样线不压卡、也不绕外圈。

**出线侧由帧内列决定。** 多列帧里，卡片只能在“朝帧外”的那一侧出线：最左列走左、最右列走右；否则线会从邻列卡片底下穿过（卡片画在线之上）。两侧都朝帧内的中间列暂时回退到按目标方向出线（已知限制）。向“反方向”的线会从帧外绕行——长，但不被卡片遮住。

**同列车道贴着本列走。** 帧内分列后，同列线程的车道从“帧的右边界空白带”改为**本列右侧的列间空隙**（该列后面还有列时）：否则横向段要从卡边一路走到帧的右边界，途中会穿过其它列的卡片——而卡片画在线之上，线就被挡住了。

**跨列线程走列间空隙，且各占车道。** 父卡在列 c、子卡在列 c+1 时，线程从父卡下缘出发，竖直段落在**两列之间的空隙（默认 20px；按跨列车道数与同列车道带一起生长，把右列推开来给竖直束让位）**里，同一空隙内按 4px 分道（否则多条线程会并成一束竖线）（这一条带在每一行都是空的），再横向进入子卡上缘。同列线程仍走帧内右侧空白带；相邻卡仍是卡间短跳。

**帧内分列：分叉才向右。** 一个帧里的卡片不再永远单列：父卡的**第一个子卡**继承父列（长链保持竖直），父卡的**其余子卡**共用一个新列（= 父列 + 1），同级同列。帧宽按**各自**的列数算，画布列距仍按最宽帧统一（避免列重叠）（`列数 × 卡宽 + 列间距`），帧高取**最高列**的行数——长链不增高、分叉才变宽。列与行的分配是纯函数，断言钉住“链不增列、分叉只加一列、同级同 x 不同 y”。

**帧内也给线留行。** 一张卡同时散出多条线程时，它们都从同一条底边出发、都跑去同一道沟槽：没有分行就会在卡边上叠成一条。现在每条走通道的线程在父卡下方占一行（5px 步进），目标侧对称地占一行；`fitChannels` 按「最大行数」加宽 `cardGap`，帧因此长高——线有了自己的空间，而不是压在卡上。车道也被夹在画布内：单列时最后那列的沟槽正落在画布边缘，未夹紧的车道会伸到画布外。

**同一道沟槽只有一条身份。** 相邻两列之间的空隙，既是左列的右沟槽、也是右列的左沟槽；早先按 `(列, 边)` 记车道，两边各算一套，于是跨这两列的线会「换道」，再去找横路——最近的横路是图的顶 margin，于是画出一条绕到画面上方的长环。现在车道按**物理沟槽**（中心线取整）记账，同一道沟槽只有一条身份：两端落在同一道沟槽里的线走一个 Z，不找横路；相邻两张卡之间的线程也直接走 8px 卡间短跳，不再绕到沟槽再折回来。

**一个版式，缩放不动几何。** 卡片尺寸固定为一个档位（`lod: 'card'`），缩放只是 transform：平移/缩放不重建 layout，线也不重算端口与折线。上一版按 `lodFor(zoom)` 换档，每次缩放都改卡片尺寸、进而重算端口与通道——读者看到的"线在跳"就是这个。代价是极小时文字不可读，那交给读者自己放大，而不是让内容变形。

**帧排布为线让路。** 通道要空间，所以布局先量后建：`fitChannels` 时 `buildCardgraph` 跑两遍——第一遍按默认间隙布线，记录每条沟槽与横路实际占了几条车道；第二遍按 `车道数 × 9px + 两侧留白` 加宽列间隙和帧间隙，再布线。于是线多的地方帧隔得开，而不是把线挤进 24px。

**悬停是一段持续的手势。** 指针落到卡片上时先是**入场**：遮罩在 200ms 内淡入、每根相关的线从悬停的那张卡片向外画出来（ease-out，越接近终点越慢，像"信号到了"）；入场之后是**行进点**：圆点按**线长**分配密度（每约 90 绘制单位一颗，长线多、短线少，所以每条线的观感一样密）；速度按**时间**计（0.0675 绘制单位/ms），不是按线长的比例——短线与长线上的点走得一样快，长线只是走得久些，不会因为线长而加速。圆点**不带尾巴**：尾巴会沿同一条折线再画一遍拐弯，读起来像"一段线在动"而不是"信号在走"。列表那一行用 160ms 过渡同时点亮。`prefers-reduced-motion: reduce` 跳过两者直接给终态。绘制仍是纯函数式的：画家只认 `hoverPhase`（入场）与 `hoverFlow`（流光位置），断言分别在 0.4、1、0.2/0.8 上检查"遮罩半透明、还没有箭头、有行进点"、"箭头齐全、遮罩不透明"、"有行进点"与"行进点位置随相位移动"。

**切换标签页只能点标签页。** 这是这版唯一一处通往平台内部的妥协：shell 只在**已挂载**的 `conversation.view` 的 props 里给 `openView`，而需要切换的恰恰是它没挂载的时候；每会话的 conversation store 是 slot 私有的，`ctx.uiConversation` 只发布注册表与 binding（binding 的 `activate` 激活的是装配 target，不是标签页）。所以 `report-tab.ts` 按**本插件自己注册的标签文字**在 `[role="tab"]` 里找到那颗标签并点它；找不到（宿主的标签条被隐藏、语言不匹配）就什么都不做，选择留在桥里，等读者自己切过去时再展开。这是写给未来的一行注脚：等 shell 给出 select-view 动词，这个文件删掉即可，其余不动。

实测（右栏，真实浏览器）：

| 场景 | 结果 |
|---|---|
| 停靠 575×619 / 4 框 5 汇报 | fit 落在 **79%**，宽度填充 **89%**，无裁剪 |
| 全屏 1279×648 | **125%**（宽度填充 87%，底部按"宽度优先"溢出，可拖看） |
| 停靠 ↔ 全屏（未手动动过） | 自动跟随：79% → 125% → 79% |
| 手动放大两步到 123% 后再全屏 | **保持 123%**，不被重算 |
| 单卡会话（1 框 1 汇报）全屏 | 封顶 **125%**，宽度只占 **26%**——不被拉伸 |
| 点卡片 / 再点一次（旧版，细节面板在画布下方） | 画布 **619 → 278 → 619**——**本版已改**：点卡片切到「汇报」展开，画布不再掉高度（见下节） |
| 滚轮（全屏 134% 时） | 下滚 120/120/44/0，总行程 284px = 溢出 260 + 两端各 12；`Ctrl+滚轮` 134% → 107% → 167% |
| 会话页标签页 | 画布数 **0**——那段「拓扑」已卸下，只剩列表 |

## 下钻：换范围，不是放大

画布原来看得见"谁和谁有往来"，但看不见"一个会话内部"——放大只能把整张图推近，框外的线照样横穿。这一版把**帧做成可以走进去的容器**：双击一个会话框（或 Tab 到它标题栏上的隐形按钮、回车），画布换成只画这条子树；面包屑 `全部 / A / B` 一级级走回去，Esc 退一级。

借的是 ComfyUI 子图的**导航**（换可见图 + 面包屑退出），不是它的文档模型：我们的图仍然是账本的派生，没有可编辑的节点、没有 CRDT、没有第二份几何。

| 决定 | 是什么 | 为什么 |
|---|---|---|
| **下钻 = 换输入** | `scopeInput(payload, reports, root)` 把 `sessions` 收窄成子树、把汇报收窄到一跳边界，`buildCardgraph` 从零重算 | 坐标空间变了：框外的帧**不存在**，它们的线落到「范围外」帧，而不是被放大推到屏幕外 |
| **边界复用「树外」帧** | 范围外的收件人与发件人落进同一只帧（下钻时标签改叫「范围外」） | 现有机制正好是"一个框装树外会话"；新造端口类型是没必要的概念 |
| **一跳边界** | 作者在范围内 **或** 任一 `from/to/cc/authors` 在范围内 | 只取作者会画出所有出边、却把"谁发给我"整段丢掉 |
| **子树两种推导** | DFS 前序切片 + `parentId` 链，两者不一致以**祖先链**为准 | 前序切片是快路径，血缘是定义；别的代码路径造出来的 payload 也能钻 |
| **depth 不归一化** | 列 = 不同 depth 值，切片后列序自然从 0 起 | 模型不需要第二条"下钻布局"代码路径 |
| **变换按范围记忆** | `Map<scopeKey, {zoom, offset, fitted}>`，进入/离开时存取 | 离开再回来要回到**读者离开时**的位置；`fitted` 标志决定回去后是否继续跟随盒子 |
| **不出第二条 fit 规则** | 仍是"按宽度、固定版式、放大不超过一步" | 上一版刚把首屏与控件统一成一条规则；下钻若按两轴 fit，就又有第二个不动点 |
| **双击进入、按钮给键盘** | 指针路径是双击（框内空白或标题栏）；帧标题栏另有一颗隐形按钮，面包屑是 `nav` 里的真按钮 | 画布没有元素可点，双击与 ComfyUI 的手势一致；按钮让键盘与读屏有确定入口 |
| **Esc 只在已下钻时监听** | 且目标可编辑则忽略 | 不跟页面抢这个键 |

**被否的替代**：`fitToFrame`（只缩放，线仍穿过相邻框）；只取作者（看不见来件）；把 `scope` 塞进 `buildCardgraph` 的选项（模型多一份状态，两个调用点要同步改）；进入时按两轴 fit（第二条 fit 规则）。

⚠️ **标题栏按钮单击不触发**：画布的 `pointerdown` 会 `setPointerCapture`，于是这一次点击的 `click` 不落到按钮上（点卡片也是靠 `pointerup` 里的算术路径打开的）。所以**指针路径定为双击**、按钮专门服务键盘与读屏；这不是没接上，是两条路各走各的。

实测（真实浏览器，本机 GUI；分支 bundle 经重启后加载，会话含 1 个子会话）：

| 场景 | 结果 |
|---|---|
| 根范围 | 面包屑「全部」、**2 框 · 1 汇报**、fit **88%** |
| 帧标题栏按钮 + 回车 | 进入子会话：面包屑 `全部 / 只回复四个字：会话已建立。`、**1 框 · 0 汇报**、**125%** |
| 双击框内空白 | 同上（指针路径） |
| Esc / 点「全部」/「上一级」 | 三条回去的路都回到 2 框；fit 视图回 **88%**，手动视图回 **137%** |
| 手动缩到 137% 后进入再返回 | **仍是 137%**——不回落到 fit |
| 手动 137% 下全屏 | **保持 137%**；点「填满宽度」得 **125%**；退出全屏后重算回 **88%**（fit 的视图跟随盒子，手动的不动） |
| 0 汇报的叶子会话 | 1 框 · 0 汇报、**125%**，不崩 |
| 控制台 | 无插件错误（唯一一条是 shell 自己的 `/api/changes.summary` 404） |

体积：客户端半 **144.74 kB → 158.17 kB** raw，gzip **41.60 → 45.08 kB**（**+3.48 kB gzip**）。raw 涨得多是因为 bundle 保留注释，而这一版加了约 250 行文档。

**已知边界**：

- **单列范围封顶 125%**：宽面板里会留白。要让它铺满就得另立一条 fit 规则（进入时按两轴），代价是第二个不动点——留给实测说话。
- **当前范围的根帧没有「进入」按钮**：进去是 no-op。payload 自己的根帧同理（它的范围就是整棵树，也就是第一级面包屑）。
- **进入/返回后焦点落回 `<body>`**：键盘与读屏读者要重新 Tab 到面包屑。可修（自动聚焦当前 crumb），本轮未做。
- **会话树只在有子会话时才有内容**：`peer_start` 与开发者模式的代理是**根会话**，不会出现在这里；只有 `subagent` 的子会话会（本机实测：验收时开的一个子会话以 depth 1 出现在时间线里；而"发布前审计"那轮的模块负责人都是根会话，所以那轮画布只有「树外」）。
- **悬停只重绘交互层**这条本轮没有重测：交互层代码未动，旧实测仍成立。
